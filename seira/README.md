# 🔁 Σειρά

Ποιος πλένει τα πιάτα αυτή τη βδομάδα;

Οι περισσότερες εφαρμογές αγγαρειών κάνουν το εύκολο: μια λίστα με checkboxes ή
έναν κύκλο «σήμερα εσύ, αύριο εγώ». Το δύσκολο δεν είναι η λίστα — είναι το
**δίκαιο**. Η Σειρά, σε κάθε γύρο, λύνει ένα πραγματικό πρόβλημα ανάθεσης
(assignment problem) με τον **αλγόριθμο Hungarian** και βρίσκει τον συνολικά
λιγότερο δυσάρεστο συνδυασμό, σταθμίζοντας τρία πράγματα μαζί:

- **τι προτιμά ο καθένας** (😀 το θέλω / 😐 αδιάφορο / 🙁 το αποφεύγω),
- **πόσα έχει ήδη κάνει** — και πόσο βαριά ήταν,
- **πόσο καιρό κολλάει στην ίδια αγγαρεία**.

Χωρίς λογαριασμούς: ένας κωδικός 6 χαρακτήρων είναι όλο το «login».

*A fair-rotation scheduler for shared chores. Each round is solved as a real
assignment problem (Hungarian algorithm) balancing stated preferences,
accumulated weighted workload, and how long someone has been stuck with the
same chore.*

---

## Εκκίνηση

Χρειάζεται μόνο **Node.js 22.5+**. Καμία εξάρτηση, κανένα `npm install`.

```bash
cd seira
npm start           # → http://localhost:3000
npm test            # 29 tests
```

| Μεταβλητή | Προεπιλογή | Τι κάνει |
|---|---|---|
| `PORT` | `3000` | Θύρα του διακομιστή |
| `DB_FILE` | `./data/seira.db` | Αρχείο SQLite |

## Πώς δουλεύει

1. **Νέος πίνακας** — άτομα και αγγαρείες, με βάρος η καθεμιά (εύκολη / κανονική / βαριά).
2. **Προτιμήσεις** — κάθε κελί του πίνακα κάνει κύκλο 😐 → 😀 → 🙁.
3. **«Βγάλε τη σειρά»** — βγαίνει ο γύρος. Όποιος λείπει, μένει εκτός με ένα κλικ.
4. **Ιστορικό & φόρτος** — φαίνεται τι έχει κάνει ο καθένας· «Αναίρεση γύρου» αν βγήκε κατά λάθος.

### Το κόστος κάθε πιθανής ανάθεσης

Για κάθε ζευγάρι *άτομο × αγγαρεία* υπολογίζεται ένα κόστος και ο αλγόριθμος
ελαχιστοποιεί το **άθροισμα** (όχι κάθε επιλογή χωριστά — γι' αυτό δεν είναι
άπληστος αλγόριθμος):

| Παράγοντας | Κόστος |
|---|---|
| «Το προτιμώ» 😀 | −6 |
| «Το αποφεύγω» 🙁 | +8 |
| Γνώμη σε βαριά αγγαρεία | ×1 έως ×2 (όχι ×3: μία προτίμηση δεν πρέπει να καθηλώνει τον πίνακα) |
| Συσσωρευμένος φόρτος | +3 ανά μονάδα πάνω από τον ελαφρύτερο, **επί το σχετικό βάρος της αγγαρείας** |
| Ίδια αγγαρεία στη σειρά | +5 ανά συνεχόμενο γύρο |
| Δεύτερη αγγαρεία στον ίδιο γύρο | +25 |

Δύο λεπτομέρειες που έκαναν τη διαφορά:

- **Ο φόρτος πρέπει να πολλαπλασιάζεται με το βάρος της αγγαρείας.** Αν είναι
  σκέτη ποινή ανά άτομο, τότε όταν τα άτομα είναι όσα και οι αγγαρείες η ποινή
  είναι ίδια σε *κάθε* συνδυασμό — άρα ακυρώνεται και ο φόρτος δεν ισορροπεί
  ποτέ. Έτσι όπως είναι, όποιος έχει κάνει πολλά σπρώχνεται προς τις ελαφριές.
- **Η ποινή επανάληψης μεγαλώνει με το σερί.** Μια δηλωμένη προτίμηση αντέχει
  έναν επαναλαμβανόμενο γύρο, όχι τέσσερις.

Και τα δύο καλύπτονται από tests που αποτυγχάνουν αν κάποιος τα «απλοποιήσει».

## Δομή

```
seira/
├── server/
│   ├── assign.js  # Hungarian algorithm + το μοντέλο κόστους
│   ├── api.js     # έλεγχοι, ιστορικό φόρτου, σερί, read model
│   ├── db.js      # SQLite (node:sqlite)
│   └── index.js   # HTTP server: REST + στατικά αρχεία
├── public/        # frontend χωρίς build: index.html, app.js, styles.css
└── test/          # node:test — 29 tests
```

Backend: Node.js (`node:http` + `node:sqlite`), μηδέν εξαρτήσεις.
Frontend: μία σελίδα vanilla JavaScript — κινητό, υπολογιστής, light & dark.

Ο αλγόριθμος ελέγχεται και με **ωμή δύναμη**: 200 τυχαίοι πίνακες κόστους
συγκρίνονται με την εξαντλητική λύση, ώστε να μην είναι απλώς «καλή» η ανάθεση
αλλά αποδεδειγμένα η βέλτιστη.

## API

Κάθε απάντηση επιστρέφει ολόκληρη την κατάσταση του πίνακα, οπότε το frontend
δεν χρειάζεται δεύτερη κλήση.

| Method | Endpoint | Τι κάνει |
|---|---|---|
| `GET` | `/api/health` | Έλεγχος ζωής |
| `POST` | `/api/boards` | Νέος πίνακας — `{ name, people: [...], tasks: [{name, weight}] }` |
| `GET` | `/api/boards/:code` | Η κατάσταση του πίνακα |
| `POST` | `/api/boards/:code/people` | Προσθήκη ατόμου — `{ name }` |
| `DELETE` | `/api/boards/:code/people/:id` | Αφαίρεση ατόμου |
| `POST` | `/api/boards/:code/tasks` | Προσθήκη αγγαρείας — `{ name, weight }` |
| `DELETE` | `/api/boards/:code/tasks/:id` | Αφαίρεση αγγαρείας |
| `POST` | `/api/boards/:code/prefs` | Προτίμηση — `{ personId, taskId, score: -1｜0｜1 }` |
| `POST` | `/api/boards/:code/rounds` | Νέος γύρος — `{ absentIds?: [...], label? }` |
| `DELETE` | `/api/boards/:code/rounds/:id` | Αναίρεση γύρου |

```bash
curl -X POST localhost:3000/api/boards \
  -H 'content-type: application/json' \
  -d '{"name":"Σπίτι Ιπποκράτους","people":["Άννα","Βασίλης","Γιώργος"],
       "tasks":[{"name":"Πιάτα","weight":2},{"name":"Μπάνιο","weight":3}]}'
```

## Σημειώσεις

- Ο κωδικός του πίνακα είναι το κλειδί: όποιος τον έχει, βλέπει και γράφει.
  Είναι σκόπιμο (μηδενική τριβή για την παρέα) — μη βάζεις εκεί ευαίσθητα δεδομένα.
- Αν αφαιρεθεί κάποιο άτομο, οι παλιοί γύροι παραμένουν αναγνώσιμοι, απλώς
  χωρίς αυτόν.
- Τα δεδομένα ζουν σε ένα αρχείο SQLite (`data/seira.db`).
